rxh.asia API 文档

开放平台提供与 OpenAI 兼容的对话接口。所有能力使用同一个 Base URL 和同一个 API Key，无需为不同模态单独接入。

Base URL · https://api.rxh.asia/v1 模型 · R-Ultra1 认证 · Bearer

01快速开始

三步完成第一次调用：在控制台创建密钥，把密钥放进环境变量，然后向接口发一条请求。

1. 创建 API Key

登录 开放平台控制台，在「API 密钥」页填写备注并创建。密钥只在创建时完整展示一次，请立即保存。

2. 配置环境变量

export RXH_API_KEY="sk-rxh-你的密钥"
$env:RXH_API_KEY = "sk-rxh-你的密钥"

02首次调用

curl https://api.rxh.asia/v1/chat/completions \
  -H "Authorization: Bearer $RXH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "R-Ultra1",
    "messages": [{"role": "user", "content": "你好"}]
  }'
import os, requests

r = requests.post(
    "https://api.rxh.asia/v1/chat/completions",
    headers={"Authorization": f"Bearer {os.environ['RXH_API_KEY']}"},
    json={"model": "R-Ultra1",
          "messages": [{"role": "user", "content": "你好"}]},
    timeout=30,
)
print(r.json())
const res = await fetch("https://api.rxh.asia/v1/chat/completions", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.RXH_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "R-Ultra1",
    messages: [{ role: "user", content: "你好" }],
  }),
});
console.log(await res.json());

返回示例（固定内容）：

03鉴权方式

所有接口都需要在请求头携带 API Key，使用标准 Bearer 格式。密钥与统一账号绑定，可在控制台吊销，吊销后立即失效。

Authorization: Bearer sk-rxh-xxxxxxxxxxxxxxxx

请勿把密钥写进前端代码或公开仓库；服务端调用时建议通过环境变量注入。

04模型列表

GET /v1/models 返回当前账号可用的模型。当前仅一个模型，能力覆盖文本、音频与视频输入。

字段说明
id模型标识，当前为 R-Ultra1
object固定为 model
owned_byrxh.asia
curl https://api.rxh.asia/v1/models \
  -H "Authorization: Bearer $RXH_API_KEY"
import os, requests
r = requests.get("https://api.rxh.asia/v1/models",
    headers={"Authorization": f"Bearer {os.environ['RXH_API_KEY']}"})
print(r.json())

05对话补全

POST /v1/chat/completions 接收消息数组并返回一条助手消息。请求体与 OpenAI Chat Completions 保持一致，现有 SDK 可直接替换 Base URL 使用。

请求参数

参数类型必填说明
modelstring是模型标识，填写 R-Ultra1
messagesarray是消息列表，元素含 role 与 content
streamboolean否是否以 SSE 流式返回，默认 false
temperaturenumber否采样温度，默认 0.7
max_tokensinteger否最大输出长度，默认 1024

返回结构

字段说明
id本次请求标识
objectchat.completion
choices[0].message.content模型生成的文本回复
choices[0].finish_reasonstop

06错误码

错误响应遵循 OpenAI 风格，error.code 可用于程序判断，error.message 仅用于排查。

HTTPcode含义与处理
401missing_api_key未携带 Authorization 头，补上 Bearer 密钥
401invalid_api_key密钥不存在或已吊销，在控制台重新创建
403account_disabled账号被停用，联系管理员
404not_found路径不存在，检查 Base URL 是否带 /v1
429rate_limited请求过于频繁，退避后重试

07限流与配额

接口按密钥维度做分钟级限流。若出现 429，请按 Retry-After 等待，不要高频重试。

08常见问题

是否兼容 OpenAI SDK？

可以。把 base_url 换成 https://api.rxh.asia/v1，api_key 换成开放平台密钥即可。

密钥泄露了怎么办？

立即到控制台「API 密钥」页吊销，再创建新密钥；旧密钥吊销后即刻失效。
