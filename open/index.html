账户充值

常见问题

充值多久到账？

对公转账通常在财务确认后的 1 个工作日内计入账户；跨行转账可能延后半天。

能否开具发票？

可以。开票主体需与签约主体一致，票面项目为“信息技术服务费”，申请后 5 个工作日内寄出。

余额会过期吗？

按合同周期结算，合同期内未使用完的额度可结转至下一周期，具体以协议为准。

说明：本页不显示任何预置余额或赠送额度，账户余额只在后台返回真实数据后展示。

接入文档

接口统一使用 HTTPS，请求与响应均为 JSON。所有接口需携带 AppID 与签名，签名算法见下文。

快速开始

v1

1. 在控制台创建应用，拿到 AppID 与 Secret（Secret 只展示一次）。

2. 用 AppID + 时间戳 + 请求体 计算 HMAC-SHA256 签名，放入 X-XH-Sign 头。

3. 先调用 /v1/ping 验证网络与签名，再接入业务接口。

4. 生产环境务必校验响应中的 request_id，便于对账与排障。

鉴权

HMAC-SHA256
# 请求头
X-XH-AppID: xh_your_app_id
X-XH-Timestamp: 1763900000
X-XH-Sign: HMAC_SHA256(secret, appid + timestamp + body)

时间戳与服务器时间相差超过 300 秒将被拒绝，防止重放。签名串中的 body 为原始 JSON 字符串，不做二次序列化。

接口列表

5 个
GET/v1/ping
连通性与签名自检，返回服务时间与版本。
POST/v1/identity
实名核验。入参 name、id_no；返回 match、checked_at。
POST/v1/enterprise
企业信息核验。入参 credit_code；返回 status、legal_person、scope。
POST/v1/address
地址标准化。入参 text；返回 province、city、district、street、confidence。
GET/v1/case
办件进度。入参 no；返回 stage、accepted_at、window。

请求示例

curl -X POST 'https://www.rxh.asia/open/api/v1/identity' \
  -H 'X-XH-AppID: xh_your_app_id' \
  -H 'X-XH-Timestamp: 1763900000' \
  -H 'X-XH-Sign: <signature>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"张三","id_no":"110101199001011234"}'

错误码

code含义处理建议
40101签名校验失败检查 Secret、时间戳与签名串顺序
40301能力未授权在控制台确认该能力已开通
42901超出频率限制按响应头 Retry-After 退避重试
42201参数格式错误核对字段类型与长度
50001上游服务不可用记录 request_id，稍后重试

频率限制

默认单应用 60 次/分钟、2000 次/日；实名核验类接口另有单独配额。需要提升时在控制台提交工单，说明业务峰值与并发。
